二、发现的问题

🟡 P1 · 本地缺 package-lock.json，依赖版本无法复现
实测：本地 yibang-server/ 没有 lock 文件；线上有（57KB）。 生产依赖 8 个（express / mysql2 / redis / jsonwebtoken / dotenv / axios / multer / cors）。
根因：部署方式是人工 scp 单个文件，lock 从没回传过本地。
影响：换一台机器重装依赖，装到的是"最新兼容版"而不是线上版本。 小版本差异在 express/mysql2 上有实际的兼容性问题先例。此时无法复现线上环境， 排查问题会多绕弯。
修复建议
从线上把 lock 拉回本地（scp root@101.201.79.119:/www/wwwroot/yibang-server/package-lock.json ./yibang-server/），之后「本地与线上装同一套」就有依据了。前提是线上这份确实是当前依赖状态 —— 拉回来后建议在本地 npm ci 试装一次确认能装上。一条命令的事。
🔵 P2 · .env 权限 644，所有本地用户都能读
实测：-rw-r--r-- root:root，other 有读权限。里面是 JWT_SECRET、数据库密码、DASHSCOPE（百炼）API Key。
影响评级说明：外网访问是 404，没有泄露到互联网，所以这不是紧急事故。 但服务器上只要以后多了任何一个以非 root 用户运行的进程（比如新人装个服务、被入侵者拿到低权限 shell）， 密钥就一并交代了。属于"现在没事、但边界不该这么宽"。
修复建议
chmod 600 /www/wwwroot/yibang-server/.env。改完 PM2 里的进程以 root 运行，不受影响。 一行命令，没有副作用。
🔵 P2 · 登录接口没有限流
实测：连发 30 次 POST /api/user/login，30 次全部正常受理（无 429）。
影响：拿不到 token（wx.login 的 code 一次性，伪造的会直接被微信拒）， 所以不是账号安全问题；但会被当成免费请求出口刷 —— 每发一次后端就真的去请求一次微信接口， 既消耗微信侧的配额，也让服务器空转。
修复建议
加最简单的同 IP 限流（如每分钟 20 次），超了返回 429。 项目里已经有 express-rate-limit 的话直接用，没有就用 redis 记一个计数器（redis 已经在用了）。 不着急 —— 当前没有真实滥用迹象。
🔵 P2 · 数据库里有个今天注册的空账号（id=14）
实测：users 表现在有 3 个 —— id=1（我的测试账号）、id=2（你本人）、 id=14（2026-09-20 注册，无昵称、未绑手机号、0 笔流水）。 流水分布：user 1 → 7 笔、user 2 → 5 笔，id=14 是空的。
可能来源：今天真机测试时用另一个微信登录过一次（换微信号 / 清了缓存重进）， 或者是测试新用户注册流程时产生的。
影响：没有功能问题。只是"账本里躺着一条查不到来源的记录"， 以后统计"有多少用户"时它会被算进去。
处理建议
先问你：这个号是不是你今天试出来的？如果是测试残留，我可以删掉（它的 0 笔流水，删了不影响任何人）； 如果是你的第二个微信号，那就留着 —— 那种情况下也建议去「我的」把手机号绑上（目前你和 id=1 都没绑， 换手机就找不回账本了）。
⚪ 待你确认 · 小程序后台的 request 合法域名
为什么列出来：这一项我在服务器和小程序代码侧都验不了 —— 它配置在 微信公众平台后台（mp.weixin.qq.com → 开发管理 → 服务器域名）。 本地 project.config.json 的 setting.urlCheck=false 只影响开发者工具， 真机上以后台配置为准。
需要确认的域名：https://api.dtzai.cn （request 必须配；uploadFile / downloadFile 如果也上传过照片或存过海报，同样要配）。
怎么验
用你自己的微信打开小程序 → 点「记一笔」→ 打一句话 → 看能不能正常入账并出现在列表里。 能入账 = 域名配好了。如果提示"不在以下 request 合法域名列表中"，就是这条。
