「辣椒3白，5块钱一斤」不算总额 · 「今天收现金1265元」归错 · 已入账记录不能改删 · 2026-09-19

一、先复现，结果比你说的更严重

把三句话原样打给 /record/ai-parse：
原话AI 当时给的问题
辣椒3白，5块钱一斤 amount=5，qty/price 都没有 把"5块钱一斤"当成总额，账少记 10 元
辣椒3包，5块钱一斤 records 为空 只能追问金额，你只好自己填
辣椒300斤，5块钱一斤 amount=1500 ✓ 它算得对
今天收现金1265元 contact=""、content="" 列表显示「未填写事由」
三条合起来说明了根因：提示词里压根没有「数量 / 单价」这个概念， 模型只能在「3白」和「5块」里瞎猜哪个是总额 —— 它不是不会算，是不稳定。 而钱的事不能"大多数时候对"。

二、怎么修的：理解交给模型，算数拿回服务端

做法为什么
提示词要求模型把 qty / unit / unit_price 都输出 只给一个 amount，服务端就没有任何依据去核对对错。
服务端 reconcileAmount() 只在能证明模型漏乘时才改 三种可证伪的形状：amount 缺失/为 0；amount 正好等于单价且数量≠1；amount 正好等于数量。 刻意不做"和 数量×单价 差得远就覆盖"——你可能给了折后总价（「3 斤 5 块一斤，一共给了 14」），那样改就是把对的改错。
收付方式用确定性词表兜底，不问模型 现金/微信/支付宝/银行/转账/扫码/赊账 是封闭集合，一个正则比模型稳，还省钱。模型给了就用模型的。
明确禁止把方式填进往来对象 否则会凭空建出一个叫「现金」的客户。清理数据时核对过：没有生成。
存下 qty / unit / unit_price / pay_method 四个字段 只存一个算出来的金额，事后谁也不知道这钱怎么来的。数量和单价留下来，列表才能把算式摆出来。
⚠️ 同一天第二次踩「提示词示例被照抄」，而且是新变种
变种一（我自己写进去的）：格式骨架写成 {"amount":0,"qty":0,…}， 模型拿不准时就原样吐回来 —— 不报错、也不返回空数组，而是给一条"字段齐全但全是 0"的记录。 改成中文占位符 {"amount":金额,"qty":数量,…} 就好了。

变种二（更阴）：收入示例里写了 "method":"现金"，结果 「卖废铁收款300元」这种压根没提方式的也被冠上 method=现金。 修法是示例里"本例确实没有"的字段一律留空，需要演示时用散文写，不要写进 JSON 行。

回归里补了 3 条反例：「今天天气不错」这类必须返回 0 笔。 只测正例的提示词改动，早晚会被照抄咬一口。

算式为什么要显示出来：你说「辣椒3斤，5块一斤」，心里本来就有个 3×5=15。 只显示一个「15.00」，你没法核对它是怎么来的，就会怀疑账本算错。 把算式摆出来，一眼就能确认。
顺带一条纪律：如果你手改了金额，那个算式就自动清掉—— 留着它会显示一个对不上的算式，比没有算式更糟。

四、左滑修改 / 删除

最近记录列表，每行左滑露出「修改」「删除」。
  • 修改复用现有的纠错面板，金额、类型、往来对象、事由、收付方式都能改。 从列表进来的修改不喂给「越用越懂」——历史记录没有"你当时说的那句话"， 喂空的会让它学出错的东西。
  • 删除走底部确认弹层，先把这条的摘要摆出来，并说明"删掉就找不回来了"。 账本数字和日报会一起变。
  • 只允许一行处于滑开状态；点别处或翻页会自动收起。竖着划仍然是翻页，不会又滚又滑。
🐛 测试过程中逼出一个真 bug（已修）
左滑原本用下标记录"手指按的是第几行"。自动化测试时有一次收尾事件没送达（工具链崩溃）， 手势悬在半空；等下一次触摸来收尾时，列表早已刷新过（刚记完一笔就会重新拉数据）， 结果把刚记的那笔滑开了。

改成按记录 id 定位，找不到就什么都不做。 这个场景等价于「你滑到一半接了个电话」——比顺顺利利滑一次有价值得多， 所以专门测了「手势中途刷新列表」，修复后不再误开任何行。
