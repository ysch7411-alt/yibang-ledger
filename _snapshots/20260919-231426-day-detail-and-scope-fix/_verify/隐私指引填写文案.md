## 一、先说结论：这一步为什么必须你亲手做

### 实测证据（不是猜的）

我在服务器上用你的 `WX_APPID` / `WX_SECRET` 取到真实的 `access_token`，实测调这个接口：

```
POST /cgi-bin/component/getprivacysetting (只读查询)
→ {"errcode":48001,"errmsg":"api unauthorized"}
```

**同一把 token 在别的接口上是好的**（对照组）：
```
POST /wxa/business/getuserphonenumber {"code":"x"}  →  {"errcode":40029,"errmsg":"invalid code"}
```
`40029` 是「code 无效」——说明 token 本身完全正常，问题**只在权限**上。

官方文档也写得很直白：

> **适用范围**：本接口支持「**第三方平台**」账号类型代调用……**其他账号类型如无特殊说明，均不可调用。**

也就是说：`setPrivacySetting` 是给**服务商代开发**用的接口（需要 `authorizer_access_token`）。
我们不是第三方平台，是你自己小程序的开发者，所以调不了。（自己猜的另外两个路径返回 `40066 invalid url`，路径本身不存在。）

**另外**：即便有接口，mp 后台登录要你本人微信扫码，我也拿不到。

```

### 4）`MessageFile` 选中的文件

```

> **注意选对 key**：官方枚举里
> `Album` = 选中的照片或视频信息 ← 我们要的是这个

## 四、其它字段（后台表单里会问到的）

| 字段 | 填什么 | 备注 |
|---|---|---|
| 开发者名称 | **重庆大头针人工智能科技有限责任公司** | 必须与后台「设置 → 基本设置 → 主体信息」**完全一致** |
| 联系方式 | 至少填一种：邮箱 / 手机号 / QQ / 微信号 | 建议专门开一个 `privacy@dtzai.cn` 并有人定期看；不要填某个人的私人号 |
| 通知方式 `notice_method` | **必填**。填：`小程序内公告（用户权益变更时在小程序内弹窗告知）` | 不填会报 `86070` |
| 存储期限 | **不填**（用微信默认话术） | 默认展示「开发者承诺…保存期限应当为实现处理目的所必要的最短时间」。我们账目要长期保存到用户注销，写死天数反而不合适 |
| 第三方 SDK | **无** | 小程序端没接任何第三方 SDK；AI 能力都在我们自己的服务端调用 |
| 存储地区 | 中国大陆（主体在境内，无需额外选） | 境外主体才必须补这一项，否则驳回 |

> 若哪天你要自己用接口提交，注意 `store_expire_timestamp` 必须填「数字+天」格式（如 `30天`），
> 填错会报 `86072`；`owner_setting` 缺字段报 `86069`。

## 五、配完之后还有一个关键节点（很多人不知道）

官方文档原文：

> 通过该接口配置用户隐私保护指引后，**对于线上版本的小程序生效，则需重新提交代码审核，
> 审核通过且需要重新发布上线后才会在小程序端生效**；
> 而对于**开发版或者体验版**的小程序，则设置后即可直接调用对应的接口。

**翻译成人话：**
- 隐私指引提交后，**你现有线上版本不会立刻生效**，必须**重新发一版**才生效
- 但**体验版/开发版**是立刻生效的

**所以推荐顺序**：
1. 在后台提交隐私指引
2. 先推一次**体验版**，在体验版里点「一键绑定手机号」验证能不能弹授权 ✅
3. 验证通过后再走正式发版流程（这时隐私指引也一起生效了）

这样不会出现「发了正式版发现手机号授权弹不出来，又要再发一版」。
